# Imagey Cloud - Agent Rules

Read these rules before starting work and always adhere to them.

## Build Instructions

- To run the backend tests successfully, the frontend must be built first with
  `mvn clean install` in `imagey-web` (or as part of a root build). This is
  required so the Pact files generated by the frontend (e.g.
  `imagey-web-imagey-server.json`) are copied and unpacked into the backend
  (`imagey-server/target/pacts`). Otherwise the backend build fails during
  `unpack-dependencies` or uses stale Pact files, causing `ContractTest` errors.

## Mandatory Development Workflow

Whenever developing a new feature or making significant changes, follow this
order of execution:

1. **Frontend development & E2E tests**: write the frontend code, then write and
   run the E2E tests (including Pact tests).
2. **Frontend linting**: verify code quality with `npm run lint` and
   `npx tsc --noEmit`.
3. **Frontend coverage & build**: run the frontend Maven build
   (`mvn clean verify` in `imagey-web`) to enforce coverage and verify the build.
4. **Backend development & tests**: write the backend code and the corresponding
   unit/integration tests to satisfy the Pact contracts generated in step 1.
5. **Backend coverage & build**: run the backend Maven build (`mvn clean verify`
   in `imagey-server`) to verify tests, coverage, and Checkstyle.

### Pact & Playwright guidelines

- **HTTP 500 errors in frontend tests**: 500 errors represent unhandled backend
  exceptions and must **NOT** end up in the Pact contracts. Do not use the Pact
  Mock Server (`provider.addInteraction()`) to mock 500 errors. Instead, use
  Playwright routing (`page.route(...)`) directly in the frontend tests (e.g.
  `errors.test.ts`).

## Manual Testing & Docker Environment

To verify complex features or E2E flows manually (registration emails, curl
requests, Playwright against a live backend):

- Run `docker compose up -d` in the project root to spin up the isolated backend
  environment, including a Mock Mail Server.
- Clean up afterwards with `docker compose down`.
- See the [Local Testing section in the README](README.md#local-testing-and-registration)
  for how to test registration and read the local Greenmail emails.
